- Shared memory is too small to explain these occupancy ceilings.
- The unified grouped kernel's resource allocation also applies when a CTA takes
  the singleton fallback. Most singleton groups therefore lose GU residency without
  gaining weight reuse. This is a plausible explanation for no material whole-model
  throughput improvement, but does not prove causality without stage timings.

Recommended bounded refinement (not implemented in this inspection):
1. Compile singleton GU/down separately from the reused branch, retaining the original
   resource budget. Make each launch skip groups outside its member-count predicate.
2. Compile a two-member reused variant for the predominant repeated-group case.
   Process larger groups in pairs, including a masked final member, so all target
   entries are computed and each pair shares one weight read/decode. This bounds
   live accumulators and metadata across every verification width, including T=5..8.
3. Begin with these two launches per stage. Additional 3-4 and 5-8 variants should
   depend on measured distribution and stage savings; four buckets would add six
   product launches per layer versus the current two-product design.
4. T<=4 capacity four alone is a useful experiment but does not protect singleton
   CTAs or guarantee the <=64 registers/thread needed for two 512-thread blocks.
5. If empty CTAs or launch costs matter, then compact groups into singleton/repeated
   ranges during the existing group kernel, publish device prefix counts, and use
   safe worst-case capacities N and floor(N/2). This can follow the simpler predicate
   prototype without changing route ordering or plan-order combination.
